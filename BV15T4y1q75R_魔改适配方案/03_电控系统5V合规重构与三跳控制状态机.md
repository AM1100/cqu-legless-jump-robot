**能改，而且改完之后比原版更适课。** 一句话概括：

> 开源版是"**2S 高电压 + 大扭矩舵机 + 视觉测距 + 轮式移动**"的通用方案；
> 我们的合规版是"**5V 单母线 + 1 颗 N20 缺齿齿轮（加载）+ 2 颗 N20（区域2 轮驱）+ 1 颗只做选位的小舵机（俯仰）+ 相位霍尔**"的方案。
> 前者在我们这里**有 2 项直接违规（电源、轮驱动）、2 项电气不可行（原版 MG946R、L298N）、2 项合规风险（雷同、AI 生成）**；后者不仅全部合规，还因为"缺齿齿轮"这个机械特性，把电控系统从"**多电机 + 到位停机 + 同步脱扣**"**降维成"单电机蓄能 + 一次到位检测 + 一路舵机选位 + 一组地面差速调向"**。
> ★**V2.1 要说清的一句**：我们确实装了轮（左右各一，区域 2 平地掉头/微调用），**但跨板那两次是整机弹射、轮在起跳瞬间被强制锁死**；"合规"靠的是状态互斥（§5.5b），不是"假装没有轮"。

### 0.2 规则口径（V1.1 已核清，不再是"待确认"）

> 附录3 §2-第4条原文："第一次跳跃从区域 1 一次跳过一块挡板（A 或 B 都行）到达区域 2；到达区域 2 之后……要在遥控状态下进行**一次反向**，然后准备进行第二次跳跃；第二次跳跃从区域 2 一次跳过**两块挡板**（A 和 B）到达区域 3。"

**PDF 的要求是"两次越障 + 中间一次遥控反向"，不是"三次越障"。** 用户说的"两次小跳 + 一次大跳（共三次跳跃）"，队长已明确为**我们的工程实现路线**，不是规则要求：

| 段 | 性质 | 是否计分 | 我们的动作 |
|---|---|---|---|
| **第 1 跳** | 越障（区域1→区域2） | **计分**（完成分 5） | 小跳档，越 A 或 B 单板 |
| **第 2 跳** | **区域2 内的一次反向** | **不计越障分**（是"反向"这个规定动作） | **脉冲式微跳掉头**，目标 180°（**未验证**，见 §7） |
| **第 3 跳** | 越障（区域2→区域3） | **计分**（完成分累计到 15） | 大跳档，一次越 A+B 双板 |

**这样"三跳"与"两跳计分"就不矛盾了**：计分只认第 1、3 跳；第 2 跳是规则点名要求的那次"反向"，只是我们选择**用跳跃的方式完成反向**（因为轮驱动被禁，见 §7）。

**⚠ 机械线同步的边界（V1.1 照办）**：
1. **每圈缺齿到安全相位必须停机**，落稳确认后才允许调姿进入下一圈；
2. **绝不盲连续三圈**（不开环连跳）——每个动作由遥控器分周期确认触发；
3. **偏航（Yaw）必须来自真实的水平切向地面冲量矩**，**左右高差本身只产生 Roll，不能当 Yaw 用**；
4. ~~**单跳完成 180° 未验证**，按"多次脉冲微跳"设计~~ ⇒ ★**V2.1 改为**：单跳 180° 由**双轮差速平地掉头**完成（不涉及跳跃），时间开环标定 `t180`，**不承诺角度精度**；
5. ★**V2.1 正式构型**：**加载 N20×1 + 轮驱 N20×2 + 俯仰舵机 P×1（无偏航舵机）**；**舵机型号未定、预算未定**。

这几条已经写进 §5（状态机强制分段确认）与 §4.4c / §5.5b（区域 2 掉头与跨板锁死）。

### 0.3 由此推出的一条策略结论（影响控制优先级）

既然完成分是三档、且"只跳成第一跳"时 **D 的难度分拿不到**，那么电控的设计优先级应该是：

**① 保"第二跳也能成"（把完成分从 5 锁到 15） > ② 追 H/D 难度分 > ③ 追求跳得漂亮。**

对应到电控上的具体取舍：
- **宁可少 3cm 跳高，也要保证"释放一次成功一次"** ⇒ 释放机制用纯机械的缺齿齿轮（抖动 <2ms），不用舵机脱扣（100~200ms 延迟 + 个体差异）；
- **宁可慢 3 秒蓄能，也要保证每次都能到相** ⇒ 卷绕占空比压低、加长蓄能时间（8s 预算足够）；
- **单次失效不能毁掉整轮** ⇒ 状态机必须能从"没跳过去/落点不对/翻倒"三种失效里远程恢复，见 §7.3 与 §5.6。

再补两条硬下限与一条"一次性机会"提醒：

- **H 最小 10cm、D 最小 20cm 是合规下限**（附录3 §2-第8条）：低于此值"H 和 D 中任意一个低于上述最小值均视为**不合规设置，不允许进行跳跃测试**"。所以 M2 的储能必须至少能越过 **H=10cm / D=20cm**，这是 §4 能量核算的**底线要求**，不是加分追求。
- **H/D 一旦确定全程不得更改**（§2-第2条）⇒ 遥控"切档"改的是**起跳角/储能档**，不是现场的板高板距。
- **难度分只有正式测试那一次机会**：补测（§2-第10条）**不计算难度分、H 固定 10cm、最高 15 分**。所以"为了追 (H−15)/5+(D−30)/5 而把 D 设得过大、结果两跳都不成"是**最差的策略**（0 分）；正确策略是**先把 H=10/D=20 做成 15 分，再逐档往上试**。

### 1.2 被"一票否决"的三项，量化后果

- **2S 供电**：不是"性能更好"的问题，是**合规测试第 3 条直接判不过**。附录 1 §1 的措辞是"M2 的供电**严格限制只允许使用**统一提供的电池模组"，§2 进一步写死"M2 **只能装备 1 组**电池模组……也**不允许搭载和使用**除该电池模组之外的**其它任何储电模块**，如太阳能板、干电池或发电机等"。这意味着：**连"多加一块小电池给舵机单独供电"这条路也堵死了。**
- **原版大舵机（MG946R 级）**：HCC1325 恒压 5V / 额定 500mA / 短时 1A。这类舵机在 5V 空载电流就有 100~200mA，带载 600mA~1A，**堵转瞬间 >1.5A** → 模块进入限流 → 母线电压塌到 3~4V → C3 掉电复位（现象：跳一次，遥控失联，机器人躺平 —— 而附录3 §2-第7条 规定**全程不许碰**，这一条会直接吃 0 分）。
- **轮驱动**：正文「项目要求」第 9 条 原文"在跨越隔板过程中的移动方式限定只能采用'跳跃'方式"，"若使用轮驱动等其它移动方式，**将取消资格**"。所以两只轮子只能作为"被动"结构件（如落地支撑），**不能主动转**。这一条要写进 D2 的风险表。

### 2.2b ★ V2.0 分时供电（这是"加了两个电机还不超流"的唯一原因）

HCC1325 额定 500mA。V1.x 时母线余量约 190mA；**再加两颗 N20 就是 370mA+，直接吃掉余量**。
所以 V2.0 不是"多接两个电机就完了"，而是把**执行器组做成互斥**：

| 状态 | 蓄能电机 | 舵机 **P×1** | 转向轮 ×2 | 母线稳态电流 | 备注 |
|---|---|---|---|---|---|
| `S1_IDLE` / `S10_WAIT_CONFIRM` | **0**（coast） | **0**（PWM 停发） | **0**（制动锁死） | ≈36 mA | 纯待机 |
| **`S2_WIND` 蓄能** | 180~260 mA | 0 | **0（锁死）** | **≈250~310 mA** ⬅ 全流程最高 | 轮被锁死，不可能叠加 |
| `S3_ARMED` 待发 | 0 | 0 | **0（锁死）** | ≈36 mA | 全部断电，靠齿轮自锁持能 |
| `S4_RELEASE` 释放 | 220 mA（45% 短脉冲） | 0 | **0（锁死）** | ≈265 mA | 越板瞬间**轮一定是 0** |
| `S5_SETTLE` / `S6_REENGAGE` | 0 / 蠕变 60mA | 0 | **0（锁死）** | ≈40~100 mA | — |
| **`S7_ALIGN` 调向** | **0（强制 coast）** | **0** | **≈180 mA** | **≈270 mA** | 蓄能电机被 `motorAllStop()` 先断 |
| `S8a_PITCH` 舵机选位 | 0 | 60~90 mA | **0（锁死）** | ≈105~145 mA | ★V2.1：只剩俯仰一路 |
| ~~`S8b_YAW`~~ | — | — | — | — | ❌ **V2.1 不可达**（偏航舵机不装机，§0） |

**结论（可以做进 D4 的一句话）**：
> 5V 母线**任何时刻只有一个执行器组吃电流**，稳态峰值出现在"蓄能"（≈310mA）而不是"蓄能+调向"（那是被互斥禁止的）。
> **稳态始终 < 320 mA**（< 500mA 额定的 64%），余量留给堵转瞬态与模块自身损耗。

**这个"分时"是写进代码的，不是写在纸上的**（固件 §7b / §5.5b）：
- `cmdWheelJob()` 第一行就 `motorAllStop()` —— 动轮之前先把蓄能电机断到 0；
- `wheelGuard()` 在 `S7` 里复核 `g_motorDuty == 0`，一旦不为 0 立刻锁轮；
- 反向：`S2` 起跳路径上轮被 `enter()` 无条件锁死，不可能"蓄能时偷偷转轮"。

> ⚠ **和 §2.2 一样，这里全是分配目标，不是实测**：2×N20 的 90mA 是按"5V / 1:150 / 轻载"估的，
> **转向轮实际电流必须台架实测**（§11 台架第 17 项）。如果实测两颗加起来超 250mA，
> 正确处置是**降 `wpct` 或换更高减速比**，不是"反正分时了就没事"。

> ⚠ **这张表是"分配目标"，不是"已通过"的证据**（V1.2 按机械线意见加注）。两点必须记住：
> ① **~310mA 不含调档瞬态**。舵机选位那 0.3s 是**另一个数**，其峰值取决于该档位的推杆力与连杆机械优势，**必须逐档实测**（§4.4b），**不能拿本表的 310mA 说"电流已经没问题"**；
> ② 本表所有电流值都是**估算**（N20 空载/堵转、舵机标称、C3 射频峰值、转向轮 2×90mA），**没有任何一项是在我们样机上测过的**。台账上要标"分配目标/估算"，实测后逐项替换。

### 2.3 三条母线纪律（写进 D4"电路设计说明"）

**纪律 1：执行器组两两互斥（同一时刻只有一组在动）。**
状态机硬约束：`S2_WIND`（蓄能电机） / `S7_ALIGN`（转向轮 ×2） / `S8a_PITCH`（俯仰舵机）**三者互斥**；`S3_ARMED` 期间**所有执行器断电（PWM 停发）**。压完后的稳态最坏值 = 电机 260 + C3 45 + 霍尔 3 + LED 6 = **314 mA < 500 mA 额定** ✓
（V2.0 新增 `S7_ALIGN`：调向时轮 180 + C3 45 + 3 + 6 ≈ **234 mA**，比蓄能还低。★V2.1：`S8b_YAW` 已随偏航舵机停用，互斥组由 4 个降为 **3 个**。）

**纪律 2：电机电流闭环限流（PWM 占空上限 + 采样反馈）。**
两级：
- **开环上限**：标定后把 PWM 占空比上限锁死在"实测 ≤300mA"对应的占空比（例如 65%），存 NVS，防止换电池/温度变化后越界；
- **闭环**：0.1Ω 采样电阻 + 运放（或直接用 INA219 的 I²C 读数），每 20ms 判一次：`I > 380mA 连续 100ms` → 占空比降一档；`I > 550mA 连续 50ms` → 立即停机 + `S9_FAULT`。
- **为什么不做硬件恒流**：5V 母线只有 1A 余量，硬件恒流电路（运放+MOSFET）在 5V 这么低的电压下压降损失太大，且 D4 要画原理图，器件越多越容易错。软件限流足够。

**纪律 3：去耦按"谁最脏谁就近"布置。**
| 位置 | 电容 | 作用（D4 里就这么写） |
|---|---|---|
| 电池模组输出端 / `TB6612FNG` 的 `VM` 就近 | **470µF/16V 电解（105℃ 低 ESR）** + 100nF 瓷片 | 吸收电机换向尖峰与无线 TX 电流脉冲 |
| 第 2 片 `DRV8833` 的 `VM` 就近 | **220µF/16V 电解** + 100nF 瓷片 | 两轮同时启动时的 µs 级浪涌 |
| H 桥输出端（并联在电机端子上） | 100nF + 1N5819 续流 | 抑制电机换向尖峰、续流 |
| N20 端子 | 100nF（贴焊在电机尾部） | 电刷火花旁路，显著降传导干扰 |
| C3 的 3V3 引脚就近 | 100nF（+ 22µF 若有旧料则加，**不在采购清单内**） | LDO 稳定与瞬态 |
| 舵机供电末端（**V2.1 只剩 1 颗**） | **100µF/16V 电解** | 舵机启动浪涌 |

> **★电容容量定案（2026-11-19，三线终核）：电解总量 $470+220+100=\mathbf{790\ \mu F}$ 标称**，即使按电解 $+20\%$ 容差上限也仅 $948\ \mu F \le 1.0\ \text{mF}$（留 $52\ \mu F$ 余量）。
> **两个组合已明确否决**：① 单只 $1000\ \mu F$（顶格、容差后 $1200\ \mu F$ 越线）；② $470\times2+100=1040\ \mu F$（超线 $40\ \mu F$）。
> **不要再往上堆容量**：按 $C=I\cdot t/\Delta V$，$1\ \text{A}$ 持续 $10\ \text{ms}$、压降 $100\ \text{mV}$ 需 $0.1\ \text{F}$（$10^5\ \mu F$）——电解对 ms 级负载台阶基本无效，$1\ \text{A}$ 峰值靠固件分时供电 + 软启动兜底。选型判据是**就近布置 + 低 ESR**，不是总容量。

> **合规提示**：附录 1 §2 禁止的是"**除该电池模组之外的其它任何储电模块**"（原文举例：太阳能板、干电池、发电机）。电容属于**去耦/滤波器件**，不是储电模块；但为免争议，我们做到两点：① 总量 **$790\ \mu F \le 1.0\ \text{mF}$**（容差上限 $948\ \mu F$ 亦不越线）；② D4 必须写明用途是"**抑制电机换向尖峰与负载瞬态**"，**绝不写成"电容蓄能/储电"**。这个措辞很关键。**量化佐证**：$0.79\ \text{mF}@5\ \text{V}$ 储能 $\tfrac12CV^2 = 9.9\ \text{mJ}$，仅为单次跳跃 $1.35\ \text{J}$ 的 $0.73\%$，物理上不可能被认定为"储电模块"。

### 2.4 电池电压监测

- 5V 经 **220kΩ / 100kΩ 分压** → GPIO3（ADC1，11dB 衰减），5.0V → 1.56V，落在 ADC 线性区。
- 判据（**阈值待实测标定**，先给起点）：`V_bat ≥ 4.75V` 正常；`4.55~4.75V` 黄灯提示"电量偏低，建议先完成跳跃"；`< 4.55V` 红灯 + 拒绝新的卷绕（只能泄能）。
- 采样时机：**只在电机停转时采**（卷绕时母线有压降，读数会假低）。这一条要在代码里坚持，否则会出现"跳一半报低电"的假故障。

### 2.5 引脚分配（ESP32-C3 SuperMini，用了 9 个，留 2 个备用）

> C3 SuperMini 可用：GPIO0~7、10、20、21（GPIO11~17 接 Flash 不可用；18/19 是 USB；8 是板载 LED、9 是 BOOT 键）。**GPIO2/8/9 是 strapping 脚，上电瞬间电平会影响启动模式。**

> ⚠ **勘误（V1.3 随固件落地发现）**：上表 GPIO2 原来写的"**下拉 10kΩ**"是**错的**。
> ESP32-C3 的 GPIO2 在启动时**必须为高**才能进入正常 SPI 启动，接下拉会导致芯片进不了正常模式（表现为"烧录成功但上电没反应"）。
> **正确接法：GPIO2 → 1kΩ 串阻 → 舵机信号；GPIO2 → 10kΩ 上拉到 3V3。** 已按上拉改正，配套 `firmware/README` §3.4 与固件注释一致。

| GPIO | 功能 | 方向 | 备注 |
|---|---|---|---|
| 0 | HALL（鼓轮相位） | 输入 | 内部上拉；开漏输出传感器直连；**只剩 1 个** |

**V2.0 引脚变化（从"9 用 2 备"变成"12 用 1 备"）**：
- 转向轮占 **GPIO7 / 10 / 20** 三根（1 路共享 PWM + 2 路方向）；
- 原规划的 **I²C（GPIO20/21）作废**：INA219 的电流闭环降级为"PWM 占空上限 + 分时供电"（§2.3 纪律 2），IMU 若要加就**不用中断模式**（轮询）。这是明确的取舍，不是遗漏。
- **为什么转向轮只用一路 PWM（不左右各一路）**：ESP32-C3 只有 **6 路 LEDC 通道 / 4 个定时器**，且通道与定时器按 `N%4` 绑定。**V2.0 定稿时**已占 3 路（俯仰舵机 ch0 50Hz/16bit、偏航舵机 ch1 50Hz/16bit、蓄能电机 ch2 20kHz/10bit），再加 2 路 → 第 5 路会落到已配成 50Hz 的定时器上，**把舵机频率改掉**（表现为舵机乱抖，极难查）。只用 4 路（ch0..ch3 各占一个定时器 T0..T3）则**结构上不可能冲突**。
  - ★**V2.1 现状**：偏航舵机不装机 ⇒ **ch1 已空出**，硬件上**已经够**给左右轮各一路 PWM。**本版仍然保持共享 PWM**，因为那是架构变更（要改 `wheelLevels()`、重标定、重写文档），不属于"清单统一"；当前"D=50% 对转 + 时间标定 180° + `wheelAsymPct` 补左右打滑差"已够区域 2 用。**今后若要单轮调速/对转软起，把 ch1 给右轮即可**，状态机/互锁/协议都不用动。
- 代价与它的实际收益：两轮占空比必须相同 ⇒ 只支持"**原地对转**"（掉头，D 固定 50%）与"**同向直行**"（D=设定值），**不支持单轮转向/曲率转弯**。这既够用（本赛题只需要掉头和对位），又**顺带堵死了"用轮子斜着蹭过挡板"的擦边路径**。

**IO 不够时的取舍顺序**（按此优先级砍）：① 砍 IMU → ~~② 砍 `SERVO_YAW`~~（★V2.1 已被构型直接砍掉，不算可选项）→ ② 砍其余非关键 IO → ③ **绝不砍转向轮**（区域2 掉头靠它）→ ④ 绝不砍霍尔。

**舵机的用法（★V2.1 只剩一颗）**：
- `SERVO_PITCH`：把**前撑杆/腿的起跳角**推到三档之一（小跳 / 中 / 大跳），到位后由**机械挡块**承力，舵机立即断电；
- ~~`SERVO_YAW`~~：❌ **不装机**。原设计里它只负责把"拍地垫/拨地摆杆的偏航方向"选到左/直/右；**V2.1 的掉头不再靠垫子，而是靠左右两个螺旋轮平地差速对转**（§4.4c / §5.5b）。所以"选向"这个自由度整个消失了。
- **舵机只做"选位"，不做"承力"，也不做"输出能量"** —— 这条是电控对机械线的硬要求（附录 1 §4 的舵机不允许被弹射反力打）。

**TB6612 接线要点（新手最容易踩的三个坑）**：
1. `STBY` 必须接 3.3V（拉低时两路全停，现象是"代码没错但电机不动"）；
2. `VM` 接 5V、`VCC` 接 3.3V（逻辑电平）、`GND` 与主控**共地**；
3. 输出端并 100nF + 1N5819，**电机尾部再焊一个 100nF**（电刷火花是无线丢包与复位的主要元凶）。

**IO 不够时的取舍顺序**（按此优先级砍）：① 砍 I²C 上的 IMU → ~~② 砍 `SERVO_YAW`~~（★V2.1 已随构型直接去掉）→ ② 绝不砍转向轮与霍尔。

## 3. 缺齿齿轮为什么是电控的"减负器"

这是整个魔改里**对电控系统价值最大**的一处改动，值得单列一节。

### 3.1 前后对比

| 环节 | 无缺齿齿轮（我们原来的路线） | 有缺齿齿轮（本方案） | 电控收益 |
|---|---|---|---|
| 蓄能到位判定 | 需要编码器/限位开关 + 减速停车 | 转到齿段末端**自动**脱啮，物理上不可能过绕 | 省一个位置闭环，**过绕烧筋的风险归零** |
| 释放 | 需要**第二颗舵机**拨叉脱扣；脱扣力对抗弹簧，容易卡死 | 缺齿区自动释放，**零执行器** | **-1 颗舵机（-4.3~9g，-1 路 PWM，-¥10~15）** |
| 释放同步 | 左右两套要同步（±10ms 误差就会歪） | **单电机集中加载 ⇒ 左右天然同步**，不存在同步问题 | 省掉同步算法与个体差异标定 |
| 待发状态 | 若用电机堵住弹簧，需**持续电流**保温 | 电机**断电**，靠齿轮自锁/棘爪保持 | **待发零电流**，不发热、不掉压、不耗电 |
| 释放时刻精度 | 舵机响应 100~200ms + 传动间隙 | 纯机械事件，**抖动 <2ms** | 起跳角重复性↑，D2/R2 的数据才有意义 |
| 复位/再蓄能 | 马达反转回零 + 拨叉复位 | 电机**继续同向转**，齿再啮合即下一循环 | 省一个"反转回零"逻辑；但**仍保留反转能力**用于遥控泄能与找齿（§4.3-③） |
| 控制代码量 | 3 个执行器状态机交织 | 1 个电机 + 1 个传感器（+2 个"选位"舵机） | 伪代码从 ~400 行降到 ~150 行，D4 流程图才画得清 |
| **连跳安全** | 脱扣后状态不明，容易开环连发 | **每圈转到缺齿安全相位必停**（物理上就是"一圈一停"），落稳确认后才允许下一圈 | **从机制上杜绝"盲目连续三圈"**（机械线明确要求，见 §0.2） |

**一句话**：缺齿齿轮把"**位置闭环 + 同步脱扣**"这个电控难题，用一个**齿形缺口**在机械上解决了。我们的电控只需要回答一个问题：**"现在齿段还剩几度？"**

### 3.2b ★ 0.2 mm 喷头电控装机公差 / 气隙实操提醒（V2.1 追加，只影响机械件，**不改固件**）

**前提与原则**：若部分/全部件改用 0.2 mm 喷头（线宽 ≈0.25 mm），**主要误差来源是"线宽量化"，不是"材料收缩"**。整体收缩补偿（scale）对 Φ3~Φ3.4 量级只有 0.006~0.02 mm，可忽略；真正要补的是**逐类配合面的孔径差值**，一律先在切片器用 `XY hole compensation` 试，**不要**直接改模型批量重打。

**① 传感器 / 磁钢（本节最相关，直接影响 `holdStopMs` 标定）**

| 项 | 0.2 mm 喷头下的处理 | 判定方法 |
|---|---|---|
| 磁钢压入孔 | 建议 Φ3.05~3.10（过盈 0.05~0.10），压入后点胶固定，**不靠弹性卡**；0.2 mm 喷头孔更接近名义，**不要再用整体 scale 放大** | Φ3 塞规 / 卡尺 |
| 霍尔—磁钢气隙 | 设计值 1~2 mm 是**标定起点，不是保证值**。0.2 mm 喷头层数多、翘曲累积更明显，必须保留 **1.0~2.5 mm 可调行程** | 装配后实测 + 逐档扫沿 |
| 传感器座定位 | **必须做成可微调**（长圆槽/垫片），不可硬定位——硬定位会把机械误差焊死进 `holdStopMs`，等于用固件追机械 | 拧松后能周向移动 |
| 2.54 mm 引脚孔 | 建议 Φ2.65~2.75（引脚 +0.15 余量）；TO-92 座留 0.2 侧面余量 | 引脚手压可入、无旷量 |
| ITR9606（备选） | 3 mm 缝隙打后**必须清缝**并塞尺校验 | 3.0 mm 塞尺通 |

**② 电机 / 齿轮配合面（跨节引用，详见机械线）**
- **`N20_Mount_Adapter` 12.4 mm 槽**：0.2 mm 喷头最易偏小 → 建议 **12.50~12.60**，四内角加 **R0.3**（防过填凸起卡死），必须拿 N20 实物做**通/止**。
- **`Servo_Gear` Φ3.2 D 孔**：**平边是 0.2 mm 喷头的死穴**（线宽量化在平边留台阶，压装正好卡平边）→ 建议圆孔 **Φ3.30~3.35**、平边到孔心 **1.55 mm**；装前用 3.0 mm 钻头柄通孔。靠 scale 补平边无效。
- **`Motor_Gear` Φ1.8 轴孔**：齿根圆仅 Φ3.38，**严禁扩到 Φ3.0**（只剩 ≈0.19 mm 薄皮必裂）→ 建议孔 **Φ1.85~1.90**、等效壁厚 ≥1.0 mm、孔口 0.3×45° 倒角；更稳的是**胶接 + 止转平面**，不靠过盈压装。

**③ 电控侧三条硬提醒**
1. **以上任何尺寸变化都只改机械件，固件一行不动**：`holdStopMs / turn180Ms / pitchJ1Deg / pitchJ3Deg / tReturnMs` 等 TBD **不受打印公差影响**，仍按 §3.3 与 §11 台架流程实测标定。**打印公差变好 ≠ 可以少标定。**
2. **禁止直接批量重打**：先出 coupon（孔径阶梯片 Φ1.7→3.5 步进 0.1 + 12.4/12.5/12.6 槽宽试片 + Φ3.2 D 孔试片），用销规/钻头柄/实物做通/止，记录实际偏差后再定补偿值。
3. **排课成本**：0.2 mm 喷头层数翻倍、路径数增约 1.6×，单件时间约 **2.2~2.7×**（总表第三节已给全套盘次与估时）。★**口径更正（2026-11-18）**：本版机械/3D 打印线已定案为**全套 0.2 mm 喷头**并完成试切验证（每辐两道连续轨迹、变线宽 0.248–0.255mm、法向壁厚 0.475–0.483mm，Arachne 参数见总表第二、三节），因此**不再是"部分件转 0.2 mm"的分治方案**。电控侧只保留一条要求：薄壁受力件（`Motor_Gear`、`Frame`、`Rack`）必须按总表的提壁数/实心修改器设置打印，并**用实物反复上弦 + 落震验证层间强度**后才装机——层间强度不足是 0.2 mm 全切的唯一实质风险，不能靠切片预览代替。

> 上述数值均为**建议起始值**，不是硬指标；最终以 coupon 通/止结果为准。

### 3.3 "提前 5° 停机"怎么实现（这是本方案的核心标定）

物理事实：**缺齿窗口相对鼓轮的角度是固定的**（由齿形加工决定），但"霍尔信号沿"相对缺齿区的角度**由装配决定**。所以不能拍脑袋写 5°，必须**标定**：

```
标定流程（一次性，结果存 NVS）：
1. 装好磁钢，手动（断电）把鼓轮转到"最后一个齿刚脱啮"的位置，
   记下此时霍尔输出状态 H_rel。
2. 手动往回（卷绕方向反）转，直到霍尔状态翻转，记下翻转沿。
3. 用角度规（或打印的刻度盘贴在鼓轮上）量出"翻转沿"到"脱啮点"的
   几何角 δ_geo（预期 3°~8°，由磁钢安装位置决定）。
4. 我们在代码里要的是停在脱啮点前的承载待发相位 **φ_hold**（与释放后的停车相位 φ_stop 不是一回事，见 §3.3b）。下面只讨论其中的几何偏置那一段： 
      φ_hold ≈ δ_geo + ε_detect + ε_delay + φ_brake + 安全余量
   ⚠ **示例写法，不是数值**：V1.1 曾把这里写成 δ_arm = δ_geo + 2°，那个 2° 只是示意余量，
   **不得当作定值** —— 机械线明确：未测前标 TBD，不给默认度数。
   如果 δ_geo 太大（>15°），说明磁钢装偏了，重新粘。
5. 把 φ_hold 换算成"电机推进的脉冲数"：
      N_arm = φ_hold / 360° × i × PPR_eff
   （i = 总减速比，PPR_eff = 每转霍尔翻转次数，若一圈一个磁钢则 =1）
6. 写入 NVS：{phase_offset, pwm_max, wind_timeout, ...}
```

**软件兜底（不依赖标定）**：ARMED 之后的"推进释放"用**固定小角度 + 电流突变判据**双保险 —— 一旦脱啮，电机负载骤降 ⇒ 电流从 250mA 掉到 <80mA，代码在 30ms 内确认"已释放"，随即进入 `S5_SETTLE`。这样即使标定偏了 ±5°，也只是释放时刻早/晚几十毫秒，不会卡死。

> ⚠ **这是"待实测"项**：磁钢位置、δ_geo、电流阈值、脱啮后的电流跌落幅度，全部要等机械线把缺齿齿轮做出来、我们上台架标定后才能定值。本文档给的是**方法**，不是结果。

#### 3.3b **两个含义完全不同的相位，不能合成一个 δ_arm**（V1.2 按机械线意见拆分）

机械线指出我把两件事混成一个量了。它们物理上不是一回事，责任方也不同：

| | **φ_hold：末齿前的承载待发相位** | **φ_stop：释放后缺齿安全停车相位** |
|---|---|---|
| 何时 | **还挂着载荷**（筋已卷满、电机仍压着末齿） | **已卸载**（脱啮之后、靠惯性/制动停下） |
| 要求 | 停早了载荷没到位、停晚了提前脱啮；必须**紧贴脱啮点之前**且带安全余量 | 必须整段落在**缺齿窗口内**，不能齿端撞齿、不能靠"运气停住" |
| 机械线给 | 末齿脱离边界（脱啮角）、齿端倒角尺寸 ⇒ **可停窗口** | 下次首齿啮合边界（再啮合角）、回程时间（齿条/齿条复位所需时间） |
| 电控线给 | 霍尔沿到脱啮点的几何角误差、检测抖动 | **停止延迟**（检测→PWM 归零）、**制动角 / 滑行角**（随转速变）、**转速**、相位检测误差 |
| 判据 | $φ_{hold}\pm\epsilon$ 全落在待发安全窗内 | $φ_{stop}\pm\epsilon$ **整段落在缺齿安全窗口内**，且**等到齿条复位**才允许再啮合 |
| 现状 | **TBD** | **TBD** |

**联合判据（谁都不能单方拍数）**：
```
φ_stop + ε_detect + ε_delay + φ_brake  <  φ_safe_max      （不撞齿）
φ_stop − ε_detect − ε_delay − φ_brake  >  φ_safe_min      （真在缺齿区）
  且  等待时间 t_wait ≥ 机械线给的回程时间 t_return      （等齿条复位）
```
其中 ε_detect、ε_delay 由电控给，φ_brake（制动/滑行角）**随转速变化，必须实测两三个转速点**，不能取单一常数。

> （$r>17.35$ 轮廓角宽≈20.4°；$r>21.788$ 齿顶圆弧≈4.5°）⇒ **"空白宽"是半径的函数，无单一值**。

> **▲▲ V1.7/V1.8 曾说过的"ε_detect 下限 ~20°"已被 V1.9 撤回（概念错误）**
> 我曾写"齿宽相位差 20° ⇒ 单点磁钢分辨力不可能优于 20° ⇒ 窄窗电子停车物理上不可能 ⇒ 必须机械正挡"。
> **这整条链是错的**：Main 是**刚体**，各 Z 相位 = 轮角 $\varphi$ + **已知几何偏置** $\theta(z)$，

> ⇒ **本节不设任何角度下限；"窗大于/小于 20°"是伪二分，不予回答。**

**结论**：**磁钢装在哪，不是机械线单方拍一个"提前角"就成立**——磁钢位置只决定几何偏置 δ_geo，最后那个停机角是"几何偏置 + 检测误差 + 停止延迟 + 制动角"四项叠加的结果，必须联合标定。**在没测之前，φ_hold 和 φ_stop 一律写 TBD，本文档不给任何默认度数**（V1.0/V1.1 里"δ_arm = δ_geo + 2°"这种写法**只作方法示意，不得作为数值使用**）。

#### 3.3c-3 ★★ 齿有宽度：不能用"齿顶中心间距"当"空白弧"（V1.6 推翻 V1.5）

> **这条是本项目最容易犯、我也确实连续犯错的换算。** V1.5 我把
> $5\times25.714\degree=\mathbf{128.571\degree}$ 写成"连续无齿弧 = φ_stop 安全窗宽度"，**是错的**。
> 郑雯文用**原始 z0 半径 CSV** 逐点复核后指出：**128.571° 是跨缺口两侧齿顶中心的 5 节距间隔，
> 绝不是连续无齿弧，更不是安全窗。齿有有限角宽，不能把齿顶到齿顶当空白。**

**三个必须分开的概念**：

| 概念 | 定义 | 能不能当停车窗 |
|---|---|---|
| **齿位栅格** | $360\degree/14=25.714\degree$ 的位置刻度 | 只是坐标系 |
| **齿顶中心间距** | 两侧齿顶中心的角向距离（缺口处 = 5 节距 = **128.55°**），**含两端齿各一部分** | ❌ 不是空白 |
| **材料空白弧** | 在**某个半径**上真正没有齿体材料的连续角度 | ⭕ 只有它才可能相关，且**随半径变化**，仍需装配验证 |

**关系式**（这是 V1.5 漏掉的关键一步）：
$$\varphi_{\text{空白}}(r) = \varphi_{\text{齿顶中心跨距}} - \varphi_{\text{轮廓角宽}}(r)$$

> ### ⚠ V1.8 修正：这里**不是"齿顶角宽"**，而且这个减法**不是独立证据**
> 我 V1.7 写"齿顶角宽约 20°，$128.55-20.4\approx108.15$ 吻合，所以反过来证明 128.571° 不是空白弧"。
> 郑雯文纠正了两点：
> 1. **20.4° 是 $r>17.35$mm 阈值下的"单齿轮廓角宽"（近根区间），不是齿顶角宽。**
>    $r>21.788$mm 的**齿顶圆弧只有约 4.5°**。
> 2. 所以 $128.55-20.4=108.15$ 之所以吻合，是因为**两个数用的是同一个 $r>17.35$ 判据**——
>    这是**同判据、同层、近根区间的自洽核对**，**不是独立证据**，不能拿去支撑任何停车结论。
>
> **更重要的推论**：既然齿顶角宽 4.5°、近根轮廓角宽 20.4°，那么
> $$\varphi_{\text{空白}}(21.788)\approx128.55-4.5=\mathbf{124.0\degree},\qquad
> \varphi_{\text{空白}}(17.35)\approx\mathbf{108.15\degree}$$
> ⇒ **"空白宽度"是半径的函数，差 16°，根本不存在唯一的"空白弧宽"。**
> 机械上真正决定能否脱开的，是 **Rack 实际接触到的那段齿高所对应的半径**——这又是一条 TBD（§10 接口 9d）。
>
> ⇒ **结论：108.15° 只能用于反证"128.571° 不等于全段无齿"，不能当窗口。**

**▲ 正确的物理描述（这一段是郑雯文的口径，也是电控唯一需要的结论）**

1. **Main_Gear 是刚体。** 给定轮角 $\varphi$，各 Z 的相位就是 $\varphi+\theta(z)$，

3. **全齿宽安全窗** = 各 Z 的窗口**映射到共同 $\varphi$ 坐标后的交集**（须在整个实际接触域上求）。

4. **检测/停车的总误差**由下列因素决定，**与齿宽相位差无关**：

#### 3.3c-4 对电控的四个直接影响（V1.6 修订）

**① 霍尔沿间隔 = 主轮一周时间（若磁钢装主轮）**
主轮一圈要电机转 2.857 圈，所以沿间隔比"电机转速"慢 2.857 倍；若磁钢误装在电机轴/输入齿轮上，
沿频率会是主轮的 2.857 倍，**相位语义全错**，`holdStopMs` 标出来的角度也差 2.857 倍。

**② `holdStopMs` 必须换算成角度才有物理意义**

$$\varphi_{hold}[\degree] \;=\; \frac{t_{hold}}{T_{\text{主轮一周}}}\times 360\degree$$

同一个 ms 值，在不同转速下角度差数倍：主轮一周 6.4s 时 30ms ≡ **1.7°**；一周只有 1.6s 时 ≡ **6.8°**。

**③ ★ 撤回 V1.5 的"一次跳跃连一圈都不要"——全周 mod 360° 相位必须保留**

V1.5 我写："按 S060 名义加载 53.31mm，一次跳跃很可能连一圈都不要 ⇒ 每圈缺齿相位改为
'每次装填行程内的缺齿位置'，**φ_stop 的定义域是本次装填走过的角度，不是整圈角度**。"
郑雯文明确否掉，**我全部撤回**，理由是她给的两条物理事实：

1. **单向周期中加载段可以 < 360°**（这一句我没错）；
2. **但回到下一次"相同缺齿轮相位"通常还须走复位空程**——齿条回位、齿轮继续同向转、
   直到缺口再次来到啮合位。**总周期仍要保留主轮 mod 360° 相位**。

⇒ 所以：
- **不能**据"10 个工作齿"推出"主轮一周只有 10 个节距"；
- **不能**删掉全周相位判据；
- **不能**改成"基于距离的停车"（郑雯文："先不改成基于距离的停车"）；

## 4. 执行器选型核算（含"为什么不用 MG946R"的量化理由）

### 4.1 卷绕电机的反解公式

已知（由机械线在 D2/D3 定，我方**要这几个数**）：

| 符号 | 含义 | 谁给 | 现值 |
|---|---|---|---|
| $F_{max}$ | 储能元件在满行程处的最大拉力 (N) | 机械线 + M1 实测 $F(x)$ | **待实测**（05 号文档 §2 的量表法） |
| $\bar F$ | 平均拉力 (N) | 同上（梯形积分 ÷ 行程） | 待实测 |
| $s$ | 卷绕行程（筋/弹簧被拉长的长度，mm） | 机械线 | 待定 |
| $r$ | 卷筒半径 (mm) | 机械线 | 待定（建议 3.5~5） |
| $i$ | 电机到鼓轮的**总**减速比 | 机械线（缺齿齿轮 + 减速箱） | 待定（298 / 380） |
| $\eta$ | 传动效率 | 机械线 | 待实测（0.4~0.7） |

计算链：

$$
n=\frac{s}{2\pi r}\ \text{(鼓轮圈数)},\quad
T_d=F_{max}\cdot r\ \text{(鼓轮峰值扭矩, N·mm)},\quad
T_m=\frac{T_d}{i\,\eta}\ \text{(电机侧所需扭矩)}
$$

$$
t_w=\frac{n}{f_{out}}\ \text{(蓄能时间, s)},\quad
f_{out}=\frac{n_{motor}}{60\,i}\ \text{(鼓轮转速, r/s)}
$$

电流估算（**仅数量级**）：$I\approx I_{stall}\cdot\dfrac{T_m}{T_{stall}}$，并要求
**$\dfrac{T_m}{T_{stall}}\le 0.45$**（留 55% 给装配误差、摩擦、温度、电池衰减）。

### 4.1b 先算"要多少能量"（这是所有选型的目标值）

把 M2 当抛体（$m=0.15$kg，$g=9.81$）：顶点高 $H=\dfrac{v_0^2\sin^2\theta}{2g}$，水平射程 $D=\dfrac{v_0^2\sin2\theta}{g}$。

| 目标 | H / D | 解出起跳角 θ | 起跳速度 v₀ | 起飞动能 $E_k=\frac12mv_0^2$ | 储能需求（$\eta=0.45$ 假设） |
|---|---|---|---|---|---|
| **合规下限**（低于此不许测试） | 10 / 20 cm | 63.4° | 1.57 m/s | **184 mJ** | **≈ 409 mJ** |
| **难度分起点**（H≥15 且 D≥30） | 15 / 30 cm | 63.4° | 1.92 m/s | **276 mJ** | **≈ 613 mJ** |
| 想再往上加（例如 H=20/D=40） | 20 / 40 cm | 63.4° | 2.21 m/s | **368 mJ** | ≈ 818 mJ |

> **三条口径提醒**：
> ① 上表是**质点抛体模型**，没有算翻转、空气阻力、离地瞬间的转动动能损失，**真实需求会比表中高**；
> ② $\eta=0.45$ 是假设值，必须用 05 号文档的**加载-卸载曲线**实测（迟滞面积就是损耗）；
> ③ "H 和 D 不能独立设"：若 D 固定为 20cm，把 H 提到 15cm，θ 就不再是 63.4°，需要重解 —— 所以**调角舵机的档位表必须与机械线的 H/D 设置一起定**。
>
> 换算到 §4.2 的算例：$\bar F\times s = 12\text{N}\times40\text{mm}=480$ mJ，**刚好在"409~613 mJ"这个区间内**，说明"1:298 + r=4mm + 40mm 行程"这套尺寸**在数量级上是对的**（这是唯一一句可以为它做的判断，具体够不够必须实测）。

### 4.2 两个算例（**全部为假设值，仅用于说明方法**）

**算例 A（假设 $F_{max}=18$N, $\bar F=12$N, $s=40$mm, $r=4$mm, $i=298$, $\eta=0.5$）**

- $n = 40/(2\pi\times4)=1.59$ 圈
- $T_d = 18\times4 = 72$ N·mm
- $T_m = 72/(298\times0.5)=0.48$ N·mm
- 典型 GA12-N20 1:298@5V：$T_{stall}\approx 120$ N·mm（1.2 kg·cm），$I_{stall}\approx 0.7$A，空载 50rpm
- 负载率 $= 0.48/120 = 0.4\%$ → **几乎空载**！$I\approx I_{noload}\approx 40$mA
- 但速度：$f_{out}=50/60=0.83$ r/s → $t_w=1.59/0.83\approx1.9$s

> **结论 A：1:298 在这个负载下"力矩大量富余、速度刚好"。** 这是好事——意味着可以用**更小的占空比**跑，电流远低于 500mA，甚至可以慢速卷绕换取平稳（占空比 40%，$t_w$ 约 5s）。

**算例 B（假设 $F_{max}=45$N, $\bar F=30$N, $s=60$mm, $r=4$mm, $i=298$, $\eta=0.45$）**

- $n=60/25.13=2.39$ 圈，$T_d=180$ N·mm，$T_m=180/(298\times0.45)=1.34$ N·mm
- 负载率 $=1.34/120=1.1\%$ → 仍在空载附近

> **结论 B：即便把拉力放大 2.5 倍，1:298 的电机的负载率也只有 1%。**
> **这说明一个反直觉的事实：N20 1:298 的瓶颈根本不是力矩，而是"能不能在 8s 内转够圈数"和"齿轮箱效率/自锁够不够"。** 所以选型的关键约束是 **$t_w$ 与自锁**，不是扭矩 → 见 4.3。

### 4.3 由 4.2 得出的三条选型结论

1. **减速比按"时间"选，不按"力矩"选**：$t_w = \dfrac{s}{2\pi r}\cdot\dfrac{60\,i}{n_{motor}}$。以 $s=40$mm、$r=4$mm、$n_{motor}=15000$rpm 估算：$i=298 \Rightarrow 1.9$s，$i=380 \Rightarrow 2.4$s。**两者都远小于 8s 目标，所以按 1:380 选更安全**（自锁更好、电流更低）。
2. **真正要担心的是"待发时会不会自己往回跑"**：N20 是**直齿行星/直齿圆柱**减速箱，理论上可反驱，只是反驱扭矩高。钢丝筋储能 480mJ 时鼓轮扭矩 $T_d\approx 72$ N·mm，折到电机轴 $T_m\approx0.5$ N·mm，而 N20 齿轮箱的**启动摩擦扭矩**通常在 5~20 N·mm 量级 ⇒ **不会反驱**，可以断电待发。**但这必须实测验证**（台架 11 项测试之一：断电保持 5 分钟不回转）。若不成立 → 加**被动棘爪**（0.5g 钢丝 + 齿）或改**蜗轮蜗杆减速电机**。
3. **驱动仍然用双 H 桥（TB6612FNG），不是 MOSFET 单向。**
   我最初按"单向卷绕"推到这里就下了"省掉 H 桥"的结论，**但对着附录 3 §1 合规测试第 5 条（全程必须可遥控，不得用手协助）重新核了一遍，这条结论不成立**：单向驱动无法反转 ⇒ 无法遥控泄能、无法"退一点再进齿"找齿、卡死后只能用手拨 ⇒ **正好命中"需要用手协助"这条 0 分门槛**。所以：
   - **主方案**：TB6612FNG（**单通道即可**，B 通道留作备用/将来加第二执行器），可正反转、可刹车、可滑行（PWM+双 IN 组合），代价 +2.2g、+¥5；
   - **降级方案**（仅当重量真的超到 35g 以上时）：AO3400 MOSFET 单向，**但必须**在机架上留**手动泄能孔**，并接受"卡死需人工干预"的风险；
   - 工程量差别很小：H 桥的多余能力（反转/刹车）在状态机里就是 `S6_REENGAGE` 的"退 2° 再进"和 `DISARM` 的反转泄能两个函数，反而让脱困手段从 1 种变成 3 种。

> 这套设计同时解决了原版"MG946R 兼做调角和承力"的所有问题，是这次魔改里第二重要的改动（第一是缺齿齿轮）。**注意：小舵机型号与预算机械线尚未选定**，本文档只按"5V 标准脉冲、选位瞬时受力"这个等级设计电流与 PWM，不锁定型号。

#### 4.4b 「不承担主弹性载荷」≠「负载扭矩为 0」（V1.2 按机械线意见补写）

机械线指出上一版有把"架构上不承力"读成"力矩为零"的风险，这是**概念错误**，必须写清：

- **"不承担主弹性载荷 / 拍地冲击"是架构要求**（力线走金属件，舵机不在力路上）；
- 但**即使弹簧完全卸载**，抬着机体调俯仰角本身仍有：**机体重力矩**、**连杆/铰链摩擦**、**连杆机构的机械优势（力臂比）损失**；
- 所以**舵机在选位瞬间的负载扭矩是有限的正数**，只是因为"瞬时 + 断电保持 + 挡块承力"而**工作时长短、不产生持续热与持续电流**。

**因此每个档位都要实测三个量（缺一不可）**：
| 测什么 | 怎么测 | 记什么 |
|---|---|---|
| **推杆力** $F_{rod}$ | 弹簧秤/推拉力计挂在推杆端，手动慢推过度到该档位 | **峰值**（不是平均），单位 gf |
| **有效力臂 / 传动效率** | 量舵机摇臂到推杆的垂直距离，及连杆几何比 | $r_{eff}$、$\eta_{link}$（估算 0.6~0.85，要标"假设"） |
| **调节电流** | 串 0.1Ω 采样或 USB 电流表，记录调档全过程波形 | **峰值 mA + 持续时间 ms + 累计电荷** |

> **纪律（机械线明确要求）**：这三个数是**"每档一个"**，不是整个机构一个数；**在测出来之前，§2.2 的 ~310mA 稳态预算不含调档瞬态，不得当作"电流已通过"的证据**。若发现"调档要顶着主弹簧推"，正确做法是**先改卸载/承载路径（让挡块或过中心连杆接手）**，**再去评估要不要换大舵机** —— 不能反过来靠加大舵机硬顶，那会把瞬时电流顶到 1A 限流上，也会把重量吃掉。

> 若实测结果与"选位、瞬时"这个等级差太远（例如某档位推杆力 >150gf 且持续 >300ms），**必须回退到机械侧改机构**，而不是在电控侧加电流。

### 4.4c ★ V2.0 转向轮：能做什么、不能做什么（写进 D4，避免被误读成"改轮式车"）

> ★**V2.1 变更定位**：偏航舵机不装机后，**"区域 2 反向"这件事的唯一手段就是本节**（原 §7 的"偏航选向 + 脉冲微跳"整体退役为**退回路径**）。
> 对应分段表：`SEGS[1]` 由 `SEG_TURN`（蓄能+微跳）改为 **`SEG_PIVOT`（不蓄能、不起跳）**，执行时它就停在 `S10_WAIT_CONFIRM` 里等操作员用 `wl`/`wr` 转 180°。

**能力边界（这是设计决定，不是能力缺失）**

| 动作 | 实现方式 | 精度来源 | 能不能做 |
|---|---|---|---|
| 原地左/右转 180° | 两轮 **等幅反向**（D 固定 50%） | `t180` 时间开环，**无编码器** | ✅ |
| 前后直线微调 N mm | 两轮 **同向**（D = `wpct` / 取补） | `wmms` 速度换算，开环 | ✅ |
| 曲率转弯 / 单轮转向 | — | — | ❌ **硬件上不可实现**（共享 PWM） |
| **跨越挡板** | — | — | ❌ **禁用**：跳的过程中轮被三重闸门锁死（§5.5b） |

**为什么"掉头固定 50% 占空比"不是省事，而是数学结果**：
共享一路 PWM ⇒ 两轮只有同一个 D。正转时平均电压 $+D\,V_m$，反转时平均电压 $-(1-D)V_m$。
两轮**等幅**必须 $D = 1-D$ ⇒ **$D = 50\%$**。所以：
- 掉头**不能用占空比调速**，只能用**时间**调速 ⇒ `t180` 是唯一的角度旋钮；
- 也**无法给对转做软启动**（任何中间 D 都会变成"一轮猛转一轮慢转"）⇒ 对转的启动电流尖峰只能靠"只在弹簧未蓄能时才允许对转"来规避。

**电流与堵转**：2×N20 同时堵转可达 1A，直接打穿 HCC1325 的短时上限 ⇒
固件层：`wpct` 默认只有 55%，掉头 50%，且**整车只有这一组在动**（§2.2b 分时）。
**但这是设计约束，不是实测结论**——转向轮实际电流见 §11 台架第 17 项，**测之前不得写"电流没问题"**。

**重量代价（诚实记账）**：双轮 + 2 只 N20 + 第二片 H 桥 ≈ **+22~24 g**，
整机从"≈104 g 结构 + 电控"推到 **126~132 g（估算）**，见 §9.3。150g 红线仍有余量，但**余量从 46g 缩到 18~24g**，
这直接压缩了"加传感器/加固结构"的空间——这是用户选择装轮的真实代价，必须写进 D4 的取舍说明。

**V2.0 新增 `S7_ALIGN` 的理由与边界**（这是**合规**上最需要说清楚的一处）：

1. **为什么调向必须是一个独立状态**：如果允许在 `S3_ARMED`（弹簧已蓄能）里转轮子，机器就是在**带着满能量在地面上动**，一旦轮子一颠就可能提前释放、摔进挡板。做成独立状态后，"转轮子"与"有能量"这两个条件在状态机层面**互斥**。
2. **入口只有两个**：`S1_IDLE`、`S10_WAIT_CONFIRM`。这两个状态的共同点是**弹簧没有蓄能**（S1 是上电/复位后的零能量态，S10 是上一跳已经卸能、只等确认）。`S2/S3/S4/S5/S6` **一个都进不去**。
3. **为什么不是"用轮子过挡板"**：PDF 第 14 页第 9 条把"轮驱跨越"列为取消资格。S7 只能从"没有能量"的状态进入，且**只要离开 S7，轮电机在状态迁移的同一瞬间就被制动锁死**（三重闸门，见 §5.5b）。所以"跳"这个动作期间轮端电压恒为 0。
4. **S7 不改变任务分段**：它对应"两次越障之间的**反向**动作"。反向从原来的"脉冲跳"改成"轮对转"，**规则上等价、实现上更可控**；脉冲掉头路径仍保留在固件里（`npulse` / `g2` 段）作为备份。
5. **S7 一定是短的**：时间到 / 收到停止 / 掉线 / 看门狗（目标时间 +1.5s）四个出口，任一触发就回原状态。不存在"一直转"的路径。

**V1.1 新增 `S10_WAIT_CONFIRM` 的理由**（机械线明确要求"绝不盲连续三圈"）：
- 每一次"选位→蓄能→释放→落稳→再啮合"算**一个完整周期**，周期结束时机器**必须停在安全态**并**等遥控器确认**；
- 这个状态**不是定时器**：它没有超时自动前进，只有收到 `CONFIRM` 才走；
- 好处：① 完全符合"每个动作由遥控器分周期确认触发"；② 一旦落点不对/姿态歪了，人工可以在确认前改用"补救动作"；③ 模式 B（半自动）只是在**人工确认**这一层由人按下"继续"，而不是靠程序自己连跳。

| `K5` **确认继续** | S10→S1（或下一段） | **★每个周期结束必须按它**，不按就停着 |

| `K7` 泄能 | S3→S1 | 遥控反转泄能，不用手碰 |
| `K8` 急停 | 任意→S1 | 立即断电机 |
| `K9` 半自动宏 | 启动段表（仍需逐段确认） | 见 §5.4 |
| **`K10` 原地调向（V2.0）** | **短按=右转180° / 长按=左转180°** | **只在 S1/S10 可用；进 S7，`t180` 时间标定** |
| **`K11` 前后微调（V2.0）** | **短按=前进30mm / 长按=后退30mm** | **同上；`wmms` 换算。GPIO2 是 strapping 脚，上电时别按** |

> （实际固件 v1.2.0：K1 预蓄能 / K2 起跳(长按) / K3 确认 / K4 急停 / K5 泄能 / K6 小跳1 / **K7 掉头步=进段2，该段不起跳** / K8 大跳3 / **K9 停轮锁死（V2.1 复用：原"加掉头脉冲"）** / **K10 调向**；★**V2.2：无 K11**（跳过 GPIO2 strapping 脚），前后微调改用手机网页，共 **10 键、无 OLED**）。
> 两处不一致是历史原因，V2.0 **不去改旧的 §5.3**（避免与已交的 D2 素材回差），只在这里标注。**V2.1 只把作废的两行划掉 + 更新本注；V2.2 只改指针与 K11 口径**。

**一次完整三跳的操作序列（模式 A，含 S10 确认闸门）**

```
① 开机自检 → LED 1 短闪
② 摆到区域1、对准 → K3 选"小跳"档（俯仰舵机 ≤0.3s 后自动断电）
③ K1 蓄能 → LED 慢闪（ARMED）  ← 此时才可以向老师示意"开始计时"
④ K2 跳 → 越单板（A 或 B）到区域2
⑤ 等 LED 变"待确认" → **K5 确认**（确认落点正常）
⑥ K4 选"左掉头/右掉头" → K1 蓄能 → K2 微跳 → 落地
⑦ K5 确认 → 若还没转到 180°，重复 ⑥（每 15~45° 一次，逐次确认）
⑧ 转到 180° 后：K3 选"大跳"档 → K1 蓄能 → K2 跳 → 越 A+B 双板到区域3
⑨ K5 确认 → 完成（或按老师要求申请结束）
```

> **注意 ⑥⑦ 的"微跳掉头"不是连续开环连跳**：每次微跳之间都停在 `S10_WAIT_CONFIRM`，由人确认姿态后再做下一次。这既满足"绝不盲连续三圈"，也满足"每个动作由遥控器分周期确认触发"。

### 5.4 模式 B：半自动宏（**每段仍需人工确认，不是"全自动连跳"**）

用户关心的"不能控制"其实是指**开环、无法中途干预**——这个担心完全正确，而且**机械线已经把"绝不盲连续三圈"定为硬边界**。所以模式 B 的定位必须改：

> **模式 B ≠ 一键跑完三跳；模式 B = 一键"记住下一步该按什么"，但每一步仍要人按 `K5` 确认。**

设计要点：

- 按 `K9` 启动段表后，机器人在每个周期结束时**不是自动前进**，而是**提示"下一步该做 X 了"**（LED 闪码 + 遥控器振动/OLED 提示），**人按 `K5` 才执行**；
- 这样：操作从"记 7 步 + 每步想清楚"变成"跟着提示按同一个键"，**减少操作失误，但不减少人工确认**；
- **遥控心跳独占（deadman）仍然保留**：一旦遥控器松手/关机/超距，机器人停在安全态（IDLE 或 ARMED），绝不继续；
- 任何时刻按 `K8` 立即中止；
- **明确不做**"定时器驱动的自动连跳"——那既违反机械线边界，也踩"是不是自主程序"的解释风险。

这样做的合规意义：机器人**离开遥控器就动不了**，本质仍是"遥控操作"，不是自主程序；同时保留"一键"带来的操作简化。

```
模式B 段表示例（三跳）：
SEG[1] = { action: ADJUST(小),  WIND, ARM, JUMP, SETTLE }        // 越单板
SEG[2] = { action: YAW(左|右) 选位, 微跳 ×N（N=3~6，每次后强制 S10 人工确认）, ADJUST(小), WIND, JUMP, SETTLE }
SEG[3] = { action: ADJUST(大), WIND, ARM, JUMP, SETTLE }          // 越双板
```

### 5.5 伪代码（可直接改写为 D4 的"程序流程图"）

```c
// ============ 全局（★V2.1：1 蓄能电机 + 2 轮驱电机 + 1 俯仰舵机 + 1 霍尔）============
// 注：下面这段是 V1.1 版伪代码，保留在 D4 素材里当"流程骨架"；V2.1 的差异只有 3 点：
//   ① S8b_YAW 不再可达（偏航舵机不装机）；② 多一个 S7_ALIGN（轮掉头，只能从 S1/S10 进）；
//   ③ seg[] 的第 2 段是 SEG_PIVOT（不蓄能不起跳，就地等轮转 180°）。
enum State { S0_BOOT, S1_IDLE, S2_WIND, S3_ARMED, S4_RELEASE,
             S5_SETTLE, S6_REENGAGE, S7_ALIGN, S8a_PITCH, S8b_YAW /*停用*/,
             S9_FAULT, S10_WAIT_CONFIRM };
State st = S0_BOOT;
Profile prof[3];          // 俯仰三档：小/中/大（脉宽）
YawDir  yaw  = YAW_STRAIGHT;   // ⚠V2.1 停用：无偏航舵机，此变量不再参与任何决策
Seg     seg[MAX_SEG];     // 段表：跳1 / ★SEG_PIVOT(地面掉头) / 跳3（每段都要人工确认）
uint8_t segIdx = 0;
uint32_t tState, lastRxMs;
bool  macroRun = false;   // 模式B：只负责"提示下一步"，不负责"自动执行"
float vbat;
uint8_t retryJog = 0;     // 找齿重试计数
uint32_t tRelease = 0;    // 脱啮时刻（用于等齿条复位 t_return）

// ★ 相位判据（V1.2）：两个相位分开判，具体窗口值全部 TBD，见 §3.3b
//   φ_hold 窗口：机械线给脱啮角边界，电控扣掉检测误差/延迟/制动角
//   φ_stop 窗口：机械线给缺齿安全窗上下界；且必须已等够 t_return 才能再啮合
bool atHoldPhase()      { /* TBD：霍尔沿 + 几何偏置 − (ε_detect+ε_delay+φ_brake) */ }
bool phaseInSafeWindow(){ /* TBD：φ_stop ± 全部误差 是否整段落在缺齿安全窗内 */ }

// ============ 安全外壳：所有执行动作的唯一入口 ============
// dir: FWD / REV / BRAKE / COAST（单电机，TB6612 A 通道）
void motorSet(uint8_t dir, uint8_t dutyPct) {
    if (mA > 550) { fault(6); return; }           // 过流保护
    dutyPct = min(dutyPct, nvs.pwmMax);           // 硬上限，防越界（标定值）
    setIN(dir);                                   // FWD:IN1=1,IN2=0 / REV:0,1 / BRAKE:1,1 / COAST:0,0
    ledcWrite(CH_PWM, dutyPct * 255 / 100);
}
void servoSel(uint8_t which, uint16_t us) {       // which: PITCH / YAW
    ledcWrite(which == PITCH ? CH_PITCH : CH_YAW, usToDuty(us));
    delay(300);                                    // 等舵机到挡块（型号未定，时间待实测）
    ledcWrite(which == PITCH ? CH_PITCH : CH_YAW, 0);   // ★到位立刻断电，0 保持电流
}

// ============ 主循环（20ms） ============
void loop() {
    Pkt p; bool got = espnowPoll(&p);            // 非阻塞
    if (got) {
        lastRxMs = millis();
        if (p.crcOk && p.cmd != CMD_NONE) onCmd(p);
        reportTelemetry();                        // 回传状态/相位/电压
    }

    // —— 丢包保护（分状态差异化，见 5.2 表）——
    if (millis() - lastRxMs > 300) {
        if (st == S2_WIND || st == S6_REENGAGE)
            abortTo(S1_IDLE);                     // 运动中失联 → 立刻停
        // S3_ARMED / S10_WAIT_CONFIRM 失联：保持不动（这两个状态本来就"什么都不做"）
    }

    switch (st) {

    case S2_WIND:
        motorSet(FWD, rampDuty(tState));           // 20ms 斜坡
        if (hallEdge() && atHoldPhase()) {         // ★到承载待发相位 φ_hold（TBD）
            motorSet(COAST, 0);
            enter(S3_ARMED);
        }
        if (millis() - tState > 12000) fault(5);   // 超时
        break;                                      // ★不在这里自动跳：必须等遥控 JUMP

    case S3_ARMED:
        // 待发：全部执行器断电，只慢闪
        ledBlink(500, 500);
        break;

    case S4_RELEASE:
        motorSet(FWD, nvs.releasePct);             // 低占空比推进，越过齿隙
        if (mA < 80 || (millis() - tState > 400)) {  // 脱啮后电流骤降
            motorSet(COAST, 0);
            tRelease = millis();                   // ★开始计齿条复位时间（t_return 由机械线给）
            enter(S5_SETTLE);
        }
        break;

    case S5_SETTLE:
        // ★落稳确认：IMU 有就用 IMU，没有就定时；不稳则延长
        if (settled() || (millis() - tState > 2000)) enter(S6_REENGAGE);
        break;

    case S6_REENGAGE:
        // ★先验证停车相位 φ_stop 落在缺齿安全窗内，且已等够齿条复位时间
        if (!phaseInSafeWindow() || (millis() - tRelease < nvs.tReturnMs)) {
            if (millis() - tState > 3000) fault(9);    // 相位/复位条件不满足 → 不硬推
            break;
        }
        motorSet(FWD, nvs.creepPct);               // 慢速找齿（齿端有导入倒角）
        if (hallEdge()) { motorSet(COAST, 0); enter(S10_WAIT_CONFIRM); }
        if (millis() - tState > 1500 && retryJog < 3) {
            motorSet(REV, nvs.creepPct);           // ★"退一点再进"——必须双 H 桥才能远程做
            if (millis() - tState > 1700) retryJog++;
        }
        if (millis() - tState > 6000) fault(7);    // 6s 仍不啮合 → 报故障
        break;

    case S10_WAIT_CONFIRM:
        // ★★ 强制人工确认闸门：无超时、无自动前进
        ledBlink(150, 150);                        // 快闪 = "等你确认"
        // 只有收到 CMD_CONFIRM 才离开（见 onCmd）
        break;
    }
}

// ============ 指令处理 ============
void onCmd(Pkt p) {
    switch (p.cmd) {
    case CMD_PITCH:    if (st == S1_IDLE)  { servoSel(PITCH, prof[p.arg].us); } break;
    case CMD_YAW:      if (st == S1_IDLE)  { yaw = p.arg; servoSel(YAW, yawUs(yaw)); } break;
    case CMD_ARM:      if (st == S1_IDLE)  { enter(S2_WIND); } break;
    case CMD_JUMP:     if (st == S3_ARMED) { enter(S4_RELEASE); } break;
    case CMD_CONFIRM:  if (st == S10_WAIT_CONFIRM) {           // ★唯一离闸通道
                           retryJog = 0;
                           if (macroRun && segIdx + 1 < segCount) segIdx++;  // 只前进一格
                           enter(S1_IDLE);
                       } break;
    case CMD_DISARM:   if (st == S3_ARMED) { disarmByReverse(); enter(S1_IDLE); } break;
    case CMD_STOP:     abortTo(S1_IDLE);                        break;
    case CMD_MACRO:    if (st == S1_IDLE)  { segIdx = 0; macroRun = true; hintNext(); } break;
    case CMD_RESET:    st = S0_BOOT;                            break;
    }
}

// ============ 遥控泄能（反转到释放位，不用手碰）============
void disarmByReverse() {
    motorSet(REV, nvs.creepPct);
    waitHallEdgeOrTimeout(3000);                   // 退回到原位即停
    motorSet(COAST, 0);
}

// ============ ⚠V2.1 停用：掉头（脉冲微跳 × N）============
// 原文保留作"退回路径"存档；正式构型无偏航舵机，现行掉头见下面 turnByWheels()
void turnPulseOnce() {
    if (st != S1_IDLE) return;                     // 一次只做一个动作
    servoSel(YAW, yawUs(yaw));                     // 1) 选方向（瞬时受力，非零扭矩）★已无此硬件
    enter(S2_WIND); waitUntil(S3_ARMED, 12000);    // 2) 蓄能到安全相位
    enter(S4_RELEASE); waitUntil(S5_SETTLE, 400);  // 3) 释放 → 腾空 → 落地
    waitSettle();                                  // 4) 落稳
    enter(S6_REENGAGE); waitUntil(S10_WAIT_CONFIRM, 6000);
    // 5) 停在 S10，等人按 K5 确认；**不自动做第二次微跳**
}

// ============ ★V2.1 现行：地面双轮差速原地掉头（不蓄能、不起跳）============
// 要点：① 只有 S1_IDLE / S10_WAIT_CONFIRM 允许（弹簧未蓄能）；
//       ② 进 S7 前先把蓄能电机彻底断开（分时供电）；
//       ③ 两轮占空比必须同为 50%（共享 PWM 的硬约束），角度靠时间 t180 开环标定；
//       ④ 结束后无条件 wheelLock()（制动锁死），再回 g_wReturn。
void turnByWheels(Dir d) {
    if (!wheelAllowed()) { wheelLock(); log("[INTERLOCK] REJ"); return; }
    motorAllStop();                                  // 蓄能电机 = 0
    setWheel(d == LEFT ? (WHEEL_L_BACK | WHEEL_R_FWD)
                       : (WHEEL_L_FWD  | WHEEL_R_BACK), 50);   // 对转 50%
    g_wReturn = st; enter(S7_ALIGN);
    waitMs(nvs.t180Ms);                              // ★纯时间开环，无编码器
    setWheel(STOP, 0); wheelLock();                   // 制动
    enter(g_wReturn);
}
```

### 5.5b ★★ 跨隔板轮驱动三重软件互锁（V2.0，合规最关键的一节）

装了轮之后，**"我们到底有没有用轮子过挡板"就变成了评委会问的第一个问题**。所以互锁不能只写在文档里，必须让代码结构本身证明它。固件 `M2_JumpRobot_ESP32C3.ino` §7b 实现三重闸门：

| # | 闸门 | 位置 | 作用 | 失效后果 |
|---|---|---|---|---|
| ① | **状态闸门** | `wheelAllowed()`：`g_state == S7_ALIGN` **且** `g_motorDuty == 0` | 只有调向态 + 蓄能电机停机时才放行 | 任何其它状态一律拒绝 |
| ② | **迁移闸门** | `enter()`：目标 ≠ `S7_ALIGN` 时无条件 `wheelLock()` | **进入蓄能/待发/释放的同一瞬间**轮就没了转矩，不存在"状态对了轮还在转"的时间窗 | — |
| ③ | **巡检闸门** | `wheelGuard()`：每个 `loop` 开头复核 | 兜住"以后有人加新状态/新指令却忘了走 `enter()`" | 发现非 S7 有力 → 立刻锁死 + 打 `[INTERLOCK]` |

外加 **④ 分时供电闸门**：S7 内若 `g_motorDuty ≠ 0`，轮立即让路。

**"锁死"到底锁成什么样**（这一点必须在 D4 里写清楚，否则会被问"你只是把占空比写 0 吧"）：

| 模式 | 输入电平 | 电机绕组 | 是否有转矩 | 何时用 |
|---|---|---|---|---|
| **制动 `wl_brake`（默认）** | 两输入同高 | 下管双开、**绕组短路** | **零驱动，且被电磁制动**（抗落地冲击、抗被挡板蹭动） | 跳、蓄能、待发、故障 |
| 高阻 `wl_hiz` | 两输入同低 | 输出 Hi-Z | 零驱动，但轮可被外力自由转动 | 需要手推机器对位时 |

**可演示的合规证据**（评委面前 10 秒就能给）：
1. 在 `S3_ARMED`（LED 慢闪）按网页/手柄的「左转 180°」→ 串口打印
   `[REJ] 调向只能在 S1_IDLE / S10_WAIT_CONFIRM 发起，当前 S3_ARMED`，轮子**纹丝不动**；
2. 在 `S2_WIND` 拔掉手柄电池 → 1s 后进入 `S9`，**轮先停再报故障**；
3. 全程 `Serial` 无 `[INTERLOCK]` 的"非 S7 有力"记录 ⇒ 说明轮在跳的过程中从未输出。

> 🔴 **不要用"我代码里没写轮驱动"来回答**。我们**确实有轮驱动代码**，合规靠的是
> **状态互斥 + 迁移瞬间锁死 + 每轮巡检**，而不是"没这个功能"。假装没有轮，反而更危险
> （评委看到轮子会直接问）。

### 5.7 时间预算（4 分钟硬约束，**V1.1 按"脉冲微跳掉头"重算**）

> ★**V2.1 现行口径**：掉头段不再做微跳。`SEGS[1]=SEG_PIVOT` 时**只做一次地面双轮掉头**：
> `t180`（**未标定，暂按 1.4 s 起调**）+ 人工判断 ≈ **8 s 内**（含确认与前后微调），
> 比下表"脉冲 ×3 ≈ 21 s"快一倍以上。**下表的微跳行只作退回路径的性能上限参考。**

| 阶段 | 设计耗时 | 计入 4 分钟? | 备注 |

| 60° | 3 次 | 3×10.1 ≈ 30 s | ≈ 55 s | 185 s | 宽松 |

| 20° | 9 次 | ≈ 91 s | ≈ 116 s | 124 s | 紧 |

> **这张表只能得出一个"内部设计目标"，不能得出一条"课程硬指标"（V1.2 更正）**：
> ①**4 分钟不是物理定律**，它只说明"在我的周期假设下，掉头转得越小余量越少"；②**每周期 10.1s 是我假设的**，一旦实测是 6s 或 14s，整张表就变；③**其余耗时我没算进去**——两次越障的加载/腾空/找齿、每次的人工确认与调姿、故障与补救余量，这些都要从 240s 里扣。
>
> 所以正确的核验式是**总账**，而不是盯单次转角：
>
> $$T_{总}=T_{两次越障}+T_{蓄能}+\sum T_{转向周期}+T_{确认/调姿}+T_{故障余量}\;\le\;240\ \text{s}$$
>
> **内部目标（我们自己的开发目标，不是课程要求，也不是物理下界）**：在上述工期假设下，把单次掉头转角做到 **30°~60°**。这只是"先追这个区间，再看总账够不够"，**30° 不是从 4 分钟或任何公式推出来的硬线**。若实测只有 20°，结论不是"违规"，而是"总账大概率超时，需要减少确认次数/提高单次转角/简化流程"——**用总账说话，不用单点阈值施压**。
>
> 另外，**3 次取均值证明不了可靠性**：均值只说明"中心位置"，不说明尾部（偶发的大横移、偶发只转 5°、偶发落地姿态差）。第 13、14 项要求**记录分布**（次数、均值、极差、失败次数），并**按最差一次估总账**。**也不能承诺"恰好三次跳跃"**——按 PDF 只需两次越障 + 一次反向，多次补正是允许的（§2-第6条）。

> ### ⚠ V1.6 新增：上表"找齿 1s"这一项很可能严重低估
> 郑雯文指出：**单向周期中加载段可以 < 360°，但回到下一次"相同缺齿轮相位"还要走复位空程，总周期仍须保留主轮 mod 360° 相位**（§3.3c-4③）。

> 上表里"找齿 1s"是按"缺口就在附近"填的，**若实测主轮一周要 4~6s，最坏情况光找齿就 4~6s，单周期 7.1s 会变成 10~12s**。

> ⇒ **不得**为了省时间而删掉全周相位判据或改成"基于距离的停车"（郑雯文明示"先不改"）。
> ⇒ 这条与 §1 的纪律一致：**先测周期，再谈掉头转角和跳跃次数**。

> 附录3 §2-第6条 允许在 4 分钟内**多次尝试**（但必须按顺序；跳过一块板失败则不允许尝试跳两块板）。所以可靠性指标不是"一次成功"，而是**"剩余时间里能重试几次"**。

### 7.1 先纠正一个物理错误（V1.0 写错了，V1.1 按机械线复核改正）

**V1.0 我写的是**："左右释放相差 Δt ⇒ 机体获得偏航力矩 ⇒ 转过 45~90°"。

**这个结论不成立，理由两条**：
1. **左右高低差/推力差主要产生 Roll（滚转），不是 Yaw（偏航）**。要让机体绕**竖轴**转，必须有**绕竖轴的力矩**，而这个力矩只能来自**地面给的、水平方向且偏离质心的切向冲量**（$M_z=r\times F_t$）。左右的"上下"差异绕的是纵轴，与 180° 掉头不是一回事。
2. V1.1 已改为**单电机集中加载**，物理上就没有"左右独立释放"这个东西了。

**正确的做法**：把"掉头"拆成两件事 —— **① 让触地冲量带一个水平切向分量；② 让这个切向分量偏离竖轴，形成力偶。**

### 7.2 四种方案对比（V1.1 重排）

| 方案 | 原理 | 额外重量 | 合规风险 | 时间成本 | 结论 |

### 7.3 Y1 的力学要点（"电控只需要选向"——★V2.1 起整节作废，仅作力学留档）

> ❌ **V2.1 作废声明**：本节描述的"斜向拍地垫 + 偏航舵机选向 + 脉冲微跳掉头"依赖**偏航舵机**，
> 而正式构型**不装偏航舵机**，`SEGS[1]` 也已改为 `SEG_PIVOT`。所以：
> **本节不再描述现行做法**，只保留"掉头必须来自真实水平切向冲量矩，而非左右高差"这一条**力学结论**（§7.1，仍然有效）。
> 现行做法见 **§4.4c**（双轮差速：$M_z$ 来自左右轮反向的地面摩擦**力偶**，同样满足 §7.1 的力学要求）。

```
        触地瞬间（俯视）
                 ↑ 弹簧压地
        ┌────────┴────────┐
        │   斜向拍地垫     │  垫面倾斜角 β
        └────────┬────────┘
                 │ 地面反力 R 分解为：
        ┌────────┴────────┐
        │ 法向 F_n（竖直） │ → 起跳（这是主功能，不变）
        │ 切向 F_t（水平） │ → 若偏离质心竖轴距离 r，则 M_z = r·F_t（★掉头的**力矩**来源；
        │                  │    要得转角还得积分成角冲量再算角速度，见下面第 3 条）
        └─────────────────┘

  偏航舵机的作用：只把"垫的斜面朝向"转到 左 / 直 / 右 三个位置之一
                  （选位后断电，由机械限位承力，不参与出力）
```

三条推论，直接约束机械设计（我会在 §10 接口表里列成"必须实测"项）：

1. **$F_t$ 的大小取决于斜面角 β 与摩擦系数** ⇒ 垫的材料与 β 必须做实验选（**不能用金属对瓷砖，会打滑到几乎没有 $F_t$**）；
2. **力臂 $r$ = 垫的切向作用线到质心竖轴的距离** ⇒ 垫越靠边，$r$ 越大，转得越多；但太大又会带来侧移与翻倒风险；
3. **量纲要走完整条链**（V1.2 更正，沿用 01 §6.1/§6.3 的角冲量写法）。$M_z=rF_t$ 只是**力矩**；$\int M_z\,dt=rJ_t$ 是**角冲量**（N·m·s）；再除以 $J_z$ 得到的是**角速度增量** $\Delta\omega_z$（rad/s），**不是转角**。转角还要再乘留空时间：

   $$\Delta L_z=\int (r_xF_y-r_yF_x)\,dt \;=\; r\,J_t \quad (\text{角冲量, N·m·s})$$
   $$\omega_z=\Delta L_z/J_z \quad (\text{rad/s})$$
   $$\boxed{\Delta\psi\approx \omega_z\,T_{留空}=\frac{r\,J_t}{J_z}\,T_{留空}} \quad (\text{rad})$$

   其中 $J_z$ 是绕竖轴转动惯量（机身越短越扁越好转），$T_{留空}$ 由起跳高度决定（01 §6.3 例：升高 0.10m ⇒ 留空 ≈0.286s；**留空越久转得越多，这也是"微跳别跳太低"的原因**）。
   **上式只是理想近似**：它忽略了离地前那一段（拍地接触期内既在加载切向冲量、又受地面约束）和落地接触段（触地瞬间的摩擦与制动既减转速也可能再给一次小角冲量）。所以**真值只能实测**，公式只用来判断"量级够不够"和"该调 $r$ 还是该调 $T_{留空}$"。
   **这些量都要实测，不能算出来就当真**；$\Delta\psi$ 的实测标定见 §11 第 13 项。

### 7.4 为什么必须"脉冲式"而不是"一次 180°"

- **单次 180° 未验证**（机械线明确说"单跳180未验证"），而且从能量与姿态看：一次大角度自旋需要很大的 $M_z\Delta t$，落地时横向速度与滚转耦合，极容易直接翻掉；
- **脉冲式更稳**：每次 30~60°，落稳后确认，再决定要不要再来一次 —— 转角**可以按需停止**（比如转到 150° 就够了，不必强求 180°）；
- **时间上算得过来**：每次微跳用"半蓄能"（≈4s），含确认约 10s，3~6 次 = 30~60s，4 分钟里有 240s（§5.7 有详细表）；
- **合规上更干净**：每次都是一次完整跳跃（全部离地 + 留空 + 再落地），没有任何"脚不离地转圈"的争议动作。

> **给 D2 的写法（★V2.1 已改口径，用这一段）**："区域 2 内的反向采用**地面双轮差速原地掉头**实现：左右轮反向对转，靠地面摩擦力偶提供偏航力矩，`t180` 时间开环标定（**待实测**），完成后**制动锁死**并立即停止输出；跨板两次均为整机弹射、**轮驱动在起跳瞬间被软件强制锁死**。单次转角**不承诺精度**（无编码器）。"
> ~~旧写法（V1.1，已作废）~~："多次脉冲微跳 + 偏航舵机选向…"——**偏航舵机不装机，不要再引用**。

### 7.5 附带能力：翻倒后的处置（**V1.1 要说实话：没有可靠自恢复**）

附录3 §2-第7条 规定全程**不许碰本体**，一旦翻倒就接近 0 分。V1.0 我写过"单侧抖跳自恢复"，**单电机架构下这个手段没有了**。所以现在的处置是：

| 手段 | 可行性 | 代价 |
|---|---|---|
| **偏航垫换向 + 微跳抖动** | 若垫的斜面能让机体"蹭"一下把一角顶起，可能翻回来；**成功率必须实测** | 每次 ~10s，可能越抖越乱 |
| **收腿重发** | 若腿可收回，重心降低后再跳，可能借落地冲击翻正 | 看机械线是否留了这个自由度 |
| **申请提前结束** | §2-第10条允许，**已得分数保留** | 放弃剩余分，但比 0 分强 |
| **被动翻正（建议机械线考虑）** | 机架外形做圆角/配重偏心，让机器人"倒下就自然滚回正位" | 结构设计阶段才能做，**现在提出来还来得及** |

> **我给机械线的建议（不是决定）**：与其指望软件翻正，不如**在结构上做成"不好翻"**——重心低、拍地垫外扩成宽支撑、上表面圆滑。这一条对分数的贡献比任何控制算法都大，因为翻倒=0 分。

## 14. 一句话总结（可直接用于汇报）

> 原版电控在我们这套规则下**活不过合规测试**：2S 供电是硬违规、MG946R 的堵转电流会把 1A 限流打穿、轮驱动会取消资格。（原版一手数据 ≈340g / MG946R / 2S 800mAh / 双 N20 75:1，见 §0.0。**V1.0 曾误写"原版 >400g / MG996R"，已更正。**）
> 改成"**HCC1325 直供 5V + 加载 N20×1 + 轮驱 N20×2 + 缺齿齿轮 + 霍尔相位 + 俯仰小舵机 ×1**"之后，不仅全部合规，还因为缺齿齿轮的"自动脱啮"特性，**把电控从多执行器同步控制降为单执行器顺序控制**，代码量降一半、待发零电流、释放抖动 <2ms，并且白拿了"计时前先蓄能"的 8 秒。
> 反向（区域 2 内 180°）**不是靠左右释放相位差**——V1.1 已撤回该说法：左右高差只产生 **Roll**，Yaw 必须有**真实水平切向地面冲量矩**（§7）。★**V2.1 现行做法**是"**左右轮反向对转，靠地面摩擦力偶产生该力矩**"（§4.4c）；原"斜向拍地垫 + 偏航舵机选向 + 脉冲微跳"**已随偏航舵机取消而退役**。
> 剩下要解决的只有三件事：**限流要标定、缺齿安全相位要标定、`t180`（双轮掉头时间）要标定**——全是台架上的事，不是原理上的事。三者现在**全部标 TBD**，一个默认度数都不给。

### 15.1 两套源码的本地位置与体量

| 来源 | 本地路径 | 体量 | 性质 |
|---|---|---|---|
| 原作者（Printables 156544 / Basement Creations V2） | `开源参考仓库/Printables_156544_Jumping_Robot/Jumping_Robot_Arduino_Code.ino` | 单文件，~400 行 | Arduino UNO/Nano 级，**无 WiFi、无状态机** |
| 复刻版（Ayson-A/Jumping-Robot） | `开源参考仓库/Jumping-Robot/main.ino` + `app_httpd.cpp` | `main.ino` ~250 行 + `app_httpd.cpp` ~750 行 | ESP32 + 摄像头 + Web 服务器（80/81 双端口） |

### 15.2 原版 Arduino 代码：读出来的三件事

1. **控制方式是"开环延时串"**：整份代码没有一句"到位了吗"，全靠 `delay()` 估算舵机转到位的时间。掉一档电压、换一颗舵机，时序就全错。
2. **弹射靠舵机拉钩**：`servo.write(释放角)` 让钩子脱开。这在我们的 5V/500mA 母线上是**不可行**的——20kg 级舵机堵转 1.5~2.5A。
3. **移动靠两个直流轮差速**：这在正文「项目要求」第 9 条下是**直接取消资格**（跨板过程只能是跳跃，轮驱动属被禁方式）。

**可借鉴的只有**：卷簧方向、缺齿/挂钩的机械时序概念、地面站立姿态。**执行器、供电、移动方式全部不可用。**

### 15.3 复刻版 ESP32 代码：读出来的三件事

1. **它是"轮式 FPV 小车"，不是跳跃机器人控制器**：`app_httpd.cpp` 的主要篇幅在 `stream_handler`（MJPEG 视频流）、`cmd_handler`（摇杆 → 双路 PWM）、以及 81 端口的第二台 httpd。
2. **没有任何安全机制**：客户端断开不会停机、没有电压监测、没有超时、没有相位判据。视频流还额外吃带宽与内存。
3. **`main.ino` 里有可用骨架**：`WiFi.softAP` + `WebServer` + 一段中文 UI 的 HTML 字符串——**这部分我们保留并改造**，其余全部丢弃。

> 另一个现实问题：摄像头、摇杆、差速这套组合与复刻仓库高度雷同，会撞附录 1 §9「独立设计」——**两个组电器相似即双双降级**。

### 15.4 从源码到固件的映射（我们保留了什么、删了什么、新增了什么）

| 功能 | 原版 Arduino | 复刻版 ESP32 | **本固件实现** |
|---|---|---|---|
| 手机遥控 | ✗ | ✓ `WebServer` + HTML | ✓ 保留骨架，**重写为三跳状态机面板** |
| 视频流 | ✗ | ✓ `app_httpd.cpp`/81 端口 | **✗ 整体删除**（无用 + 雷同风险） |
| 摇杆 / 差速 | ✓ 双轮 | ✓ 双轮 | **✗ 删除**（轮驱动取消资格） |
| 蓄能执行器 | 大舵机 | 双 N20 | ✓ **1× N20 + 30ms 斜坡** |

### 15.7 顺带修掉的一处硬件错误（**重要**）

本文档 §2.5 曾写"GPIO2 加 1kΩ 串阻 + 10kΩ **下拉**"——**错的**。
ESP32-C3 的 strapping 脚是 **GPIO2 / GPIO8 / GPIO9**，**GPIO2 启动时必须为高**；接下拉会导致芯片进不了正常启动。

**已改为**：GPIO2 → 1kΩ 串阻 → 舵机信号；GPIO2 → 10kΩ **上拉**到 3V3。
固件配套接线表（README §3.4）已按上拉执行，§2.5 表格已同步。

### 15.8 固件**不能**替你做的事（诚实清单）
